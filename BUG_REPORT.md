Generated by comprehensive code review of all 7 source files (commit `c44c15a`, branch `main`).

## 🔴 Critical Bugs

### 1. `tesseract.ts` — `convertPdfPage` silently ignores failures
**File:** `extensions/tesseract.ts:66-74`  
`execCapture()` returns `{ stdout, stderr, code }` but the function never checks the exit code. If `sips` or `pdftoppm` fail, the function returns successfully and tesseract runs on a missing or corrupt PNG.

```typescript
async function convertPdfPage(pdfPath: string, pageIndex: number, outPath: string): Promise<void> {
    if (process.platform === "darwin") {
        if (pageIndex === 0) {
            await execCapture("sips", ["-s", "format", "png", pdfPath, "--out", outPath]);
            return;  // ← does NOT check if sips succeeded
        }
    }
    await execCapture("pdftoppm", [...]);  // ← does NOT check exit code
}
```

Compare with `ollama.ts:convertPdfPageMac()` which properly checks `pdftoppm` output and throws on failure:

```typescript
if (!existsSync(outPath) || readFileSync(outPath).length === 0) {
    throw new Error(`pdftoppm produced no output for page ${pageIndex + 1}`);
}
```

**Fix:** Check `result.code` and throw if non-zero, or check that the output file exists and has content.

### 2. `mineru-pro.ts` — `require()` mixed with ES `import` statements
**File:** `extensions/mineru-pro.ts:87, 114, 124`  
The file uses ES module `import` at the top level but raw `require()` in function bodies:

```typescript
import { readFileSync, mkdtempSync, readdirSync } from "node:fs";  // line 16

// Later:
require("node:fs").writeFileSync(zipPath, buf);     // line 87
const { execFile } = require("node:child_process");  // line 114  
require("node:fs").rmSync(dir, { ... });             // line 124
```

This only works because the project defaults to CommonJS (no `"type": "module"` in `package.json`). If the project ever transitions to ESM, all three `require()` calls will throw `ReferenceError: require is not defined`.

**Fix:** Replace with direct function calls using existing imports, or add the missing imports:
- `writeFileSync` is already imported — use it directly
- Import `execFile` from `node:child_process` at top
- Import `rmSync` from `node:fs`

## 🟠 High-Severity Bugs

### 3. `pix2text.ts` — Stderr JSON parsing breaks on chunk boundaries
**File:** `extensions/pix2text.ts:117-128`  

```typescript
child.stderr.on("data", (d) => {
    const text = d.toString("utf8").trim();
    for (const line of text.split("\n")) {
        const trimmed = line.trim();
        if (!trimmed.startsWith("{")) continue;
        try {
            const p = JSON.parse(trimmed);
```

When a JSON progress line is split across two stderr chunks (e.g., TCP congestion, large payloads), the JSON is never valid and gets silently dropped:

```
Chunk 1: {"status": "page", "page": 1, "total": 10}\n{"status": "pag
Chunk 2: e", "page": 2, "total": 10}\n
```

"pag" is not valid JSON → silently skipped. The second chunk's trailing fragment is also skipped. Pages 1 and 2 progress are never reported.

**Fix:** Buffer incomplete lines between chunks:

```typescript
let lineBuffer = "";
child.stderr.on("data", (d) => {
    lineBuffer += d.toString("utf8");
    const lines = lineBuffer.split("\n");
    lineBuffer = lines.pop() || "";  // keep incomplete line
    for (const line of lines) {
        // ... parse JSON ...
    }
});
```

### 4. `pix2text.ts` — Race condition in temp file paths
**File:** `extensions/pix2text.ts` (Python embedded script)  

```python
tmp_path = f"/tmp/pi-p2t-page-{os.getpid()}-{i}.png"
```

If two pi-ocr processes run pix2text simultaneously on different files, they share the same PID namespace (same Node.js process) and will overwrite each other's temp files. The path only uses PID + page index, not a unique identifier.

**Fix:** Use Python's `tempfile` module:
```python
import tempfile
with tempfile.NamedTemporaryFile(suffix=".png", delete=False) as f:
    f.write(img_bytes)
    tmp_path = f.name
```

### 5. `mineru.ts` — `pollTask` does not check HTTP status
**File:** `extensions/mineru.ts:100-103`  

```typescript
async function pollTask(taskId: string, timeoutMs: number, ...): Promise<string> {
    const resp = await fetch(`${BASE_URL}/parse/${taskId}`, {
        signal: AbortSignal.timeout(10_000),

    const data = (await resp.json()) as { code: number; data: {...} };
    // ← Missing: if (!resp.ok) { ... }
```

If the poll endpoint returns `429 Too Many Requests`, `502 Bad Gateway`, or any non-200 status, the code tries to parse the response body as JSON. If the body isn't valid JSON (e.g., HTML error page from a gateway), `resp.json()` throws an unhelpful `SyntaxError`.

**Fix:** Add `resp.ok` check before JSON parsing, like `apiPost` already does.

### 6. `mineru.ts` — No per-chunk size check after PDF splitting
**File:** `extensions/mineru.ts:186-210`  

When `pageCount > 20` and `splitPdf` is enabled, the PDF is split into ≤20-page chunks, but each chunk's file size is never checked against the 10MB limit. A high-resolution scanned PDF could produce individual chunks well over 10MB, causing silent failures at upload time.

```typescript
const chunkName = `${fileName.replace(/\.pdf$/i, "")}_p${chunk.firstPage}-${chunk.lastPage}.pdf`;
const markdown = await mineruProcessFile(chunk.path, chunkName, prefix, onProgress);
// mineruProcessFile checks size and throws if >10MB, but with poor UX:
// "File too large" error mid-batch after already processing other chunks
```

**Fix:** Check chunk sizes before starting processing, warn if any exceed 10MB, and skip those chunks.

## 🟡 Medium-Severity Bugs

### 7. Signal/abort not connected to fetch calls
**Files:** `mineru.ts`, `mineru-pro.ts`, `pix2text.ts`  

All backends accept `signal: AbortSignal | undefined` but none pass it to `fetch()` or `spawn()`. The signal is only checked manually as `signal?.aborted` between iterations (in `mineru.ts` and `tesseract.ts`), or ignored entirely (in `mineru-pro.ts` and `pix2text.ts`).

This means:
- In-flight HTTP requests cannot be cancelled — they drain battery and bandwidth uselessly
- `spawn()` child processes keep running after cancellation
- Abort is "eventual" rather than immediate

**Fix:** Pass `signal` to all `fetch()` calls and call `child.kill()` on abort for spawned processes.

### 8. `mineru-pro.ts` — `downloadAndExtractMd` loads entire zip into memory
**File:** `extensions/mineru-pro.ts:82-83`  

```typescript
const resp = await fetch(zipUrl, { signal: AbortSignal.timeout(120_000) });
const buf = Buffer.from(await resp.arrayBuffer());
require("node:fs").writeFileSync(zipPath, buf);
```

MinerU Pro supports files up to 200MB. The result zip could be large, and this buffers the entire download in memory before writing to disk. On systems with limited RAM, this risks OOM.

**Fix:** Stream the response to disk using `fs.createWriteStream()` and a `ReadableStream` pipe, or use `fetch` → `response.body.pipeTo(writable)`.

### 9. `tesseract.ts` — No multi-page PDF conversion fallback on macOS
**File:** `extensions/tesseract.ts:66-74`  

```typescript
async function convertPdfPage(...): Promise<void> {
    if (process.platform === "darwin") {
        if (pageIndex === 0) {
            await execCapture("sips", [...]);
            return;
        }
    }
    await execCapture("pdftoppm", [...]);
}
```

For page 0 on macOS: uses `sips`, then falls through to try `pdftoppm` too (note: no `return` after `if (pageIndex === 0)`). Wait — there IS a `return` on line 71. Let me re-check...

Actually looking at the code: the `return` on line 70 is inside the `if (pageIndex === 0)` block, so page 0 returns after sips, and pages 1+ fall through to `pdftoppm`. This means pages 2+ on macOS require `pdftoppm` (poppler). Without it, they fail silently (bug #1 above means the error is swallowed).

Compared to `ollama.ts` which has a proactive startup check warning the user to install poppler, `tesseract.ts` has no such check.

**Fix:** Add a `pdftoppm` availability check during startup, matching `ollama.ts` behavior.

### 10. `mineru.ts` — `getPdfPageCount` dynamic import on every call
**File:** `extensions/mineru.ts:150`  

```typescript
const { getPdfPageCount } = await import("./ollama");
```

This dynamically imports `ollama.ts` on every call to `mineruOcr()`. Dynamic imports are cached by Node.js (the module is only loaded once), so this isn't a performance bug per se, but it adds unnecessary async overhead and makes the dependency implicit.

**Fix:** Use a top-level import (as `tesseract.ts` already does).

### 11. `pix2text.ts` — `_task` parameter unused
**File:** `extensions/pix2text.ts:127`  

The PIX2TEXT_ENGINE script receives and uses `task` (line 32: `task = sys.argv[2]`), but looking at the Python code, `task` is never actually used to configure the OCR behavior. The pipeline always runs the same `p2t.recognize()` call regardless of whether the user requested "text", "formula", "table", or "auto".

This means Pix2Text always produces the same output regardless of the task parameter, which is misleading to users.

**Fix:** Either implement task-specific behavior (e.g., for "formula" task, use `p2t.recognize_formula()`) or document that task is ignored for this backend.

### 12. `ollama.ts` — `getPdfPageCount` falls through to Linux on macOS
**File:** `extensions/ollama.ts:82-99`  


Two separate `if` blocks means `pdfinfo` is tried on macOS if `mdls` fails. If `pdfinfo` is installed via poppler, it gives a potentially different page count. Not a correctness issue (both should agree), but the intent is unclear.

### 15. `mineru-pro.ts` — `cleanMarkdown` regex too strict
**File:** `extensions/mineru-pro.ts:192`

### 17. `index.ts` — `execute` detail keys can be overwritten
